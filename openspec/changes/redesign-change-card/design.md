## Context

Макет: панель 400 px, секции без сворачивания. Данные частично есть в `detail` (status, apply), частично нет: дельты, разделы задач, счётчики замечаний, прочие связи тредов.

## Decisions

- **Дельты** — `openspec show <id> --json --deltas-only`: поля `spec` и `operation`. Вызов только если существует `openspec/changes/<id>/proposal.md`: без него CLI 1.9 отвечает ошибкой `show_error`. Строка дельты сопоставляется пути `openspec/changes/<id>/specs/<spec>/spec.md`.
- **Разделы задач.** CLI не сообщает трекинг-файл (`apply.tracks` схемы). Берётся единственный файл артефакта, чьи строки-чекбоксы (паттерн OpenSpec `^\s*[-*]\s*\[([\sxX])\]\s*(.*)`) по порядку совпадают с `apply.tasks` по тексту и `done`. Разделы — заголовки `##`. Нет совпадения — `sections: null`, показывается только общий прогресс. Это проверка, а не догадка: несовпадение не маскируется.
- **Счётчики замечаний** — RPC `reviewStats(scope, paths)`: по живой генерации документа (`missing=0`) — `drafts` (status draft) и `open` (sent/replied). Документ без записи — нули: замечаний действительно нет.
- **Прочие связи треда** — из уже загруженного `links`, без нового RPC.
- **Навигация** — `ItemDetail` хранит выбранный путь; строка открывает `ReviewDocument`, кнопка «назад» возвращает к карточке. Фокус — на заголовок открытого вида.
- **Стили** — токены темы BB (Tailwind-классы проекта), не цвета макета; структура, отступы и типографика — по макету.

## Risks

- Лишний вызов CLI на каждое открытие карточки (+1 процесс). Приемлемо: detail уже вызывает два.
