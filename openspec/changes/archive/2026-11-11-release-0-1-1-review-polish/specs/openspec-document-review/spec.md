## MODIFIED Requirements

### Requirement: Встроенное Markdown-ревью

Плагин SHALL позволять читать Markdown, выделять текст и создавать комментарии к фрагменту либо всему документу. Колонка комментариев SHALL показываться и скрываться переключателем с явной подписью действия и числом комментариев. При достаточной ширине панели документ и колонка SHALL отображаться рядом; в узкой панели колонка SHALL целиком заменять документ. Обсуждение SHALL работать без установки исходного Doc Review и не изменять исходный файл само по себе.

#### Scenario: Замечание к требованию
- **WHEN** пользователь выделяет фрагмент spec.md
- **THEN** рядом с выделением появляется кнопка добавления замечания
- **AND** нажатие открывает форму рядом с выделением, в пределах ширины правой панели, и переводит фокус в поле ввода
- **AND** сохранение создаёт открытый комментарий с привязкой к исходному документу без изменения его содержимого

#### Scenario: Узкая панель
- **WHEN** панель уже 720 CSS px и пользователь включает комментарии
- **THEN** вместо документа показывается список комментариев, а выбор комментария возвращает документ с подсветкой его цитаты

#### Scenario: Широкая панель
- **WHEN** панель не уже 720 CSS px и комментарии включены
- **THEN** документ и список комментариев видны рядом без горизонтального переполнения, разделённые вертикальной границей

#### Scenario: Переключатель колонки
- **WHEN** колонка комментариев скрыта или показана
- **THEN** переключатель подписан соответственно «Показать комментарии · N» или «Скрыть комментарии · N», где N — число комментариев документа

### Requirement: Явная передача агенту

Плагин SHALL ставить комментарии в очередь текущего треда только по действию пользователя: один открытый комментарий или все открытые комментарии документа. Сообщение SHALL состоять из видимой пользователю части на языке интерфейса — заголовок с именем файла и числом комментариев, затем для каждого комментария его номер как на подсветке, текст и цитата блоком — и скрытой от пользователя части для агента на английском с идентификаторами, путём документа, цитатами, текстом комментариев и командой закрытия. Видимая часть SHALL NOT содержать идентификаторы комментариев. Агент SHALL закрывать комментарий командой `bb openspec review resolve <id>` только для комментариев, отправленных в его тред; команды исходного Doc Review SHALL NOT изменять его независимое хранилище.

#### Scenario: Отправка одного комментария
- **WHEN** пользователь отправляет в очередь один открытый комментарий
- **THEN** тред получает сообщение в режиме очереди; комментарий переходит в «отправлен», если BB сразу передал сообщение, иначе — в «в очереди»

#### Scenario: Сообщение покинуло очередь
- **WHEN** BB передаёт сообщение из очереди в переписку
- **THEN** комментарий переходит в «отправлен»

#### Scenario: Пользователь убрал сообщение из очереди
- **WHEN** пользователь удаляет сообщение из очереди треда до передачи агенту
- **THEN** комментарий возвращается в «открыт», его можно редактировать и отправить снова

#### Scenario: События очереди пропущены
- **WHEN** плагин загружается, а у комментария статус «в очереди»
- **THEN** строка ещё в очереди треда — статус сохраняется; видимая часть сообщения, пересобранная из его комментариев на любом поддерживаемом языке, есть в истории промптов треда — «отправлен»; иначе — «открыт»

#### Scenario: Удаление или закрытие комментария в очереди
- **WHEN** пользователь удаляет или закрывает комментарий в статусе «в очереди»
- **THEN** плагин одним действием убирает его сообщение из очереди треда; другие комментарии того же сообщения возвращаются в «открыт»; если сообщение уже покинуло очередь, действие всё равно выполняется

#### Scenario: Отправка всех
- **WHEN** пользователь нажимает «Отправить все в чат» в закреплённой верхней панели документа
- **THEN** все открытые комментарии документа уходят одним сообщением и переходят в состояние «отправлен»

#### Scenario: Ошибка доставки
- **WHEN** BB не принимает сообщение
- **THEN** комментарии остаются открытыми и не показываются как отправленные

#### Scenario: Агент закрывает комментарий
- **WHEN** агент выполняет `bb openspec review resolve <id>` в треде, куда комментарий был отправлен
- **THEN** комментарий становится закрытым; из другого треда команда отклоняется

#### Scenario: Формат сообщения
- **WHEN** пользователь отправляет комментарии №2 и №5 к design.md
- **THEN** пользователь видит в чате «Комментарии к design.md · 2», блоки «Комментарий №2» и «Комментарий №5» с текстом и цитатой, без идентификаторов
- **AND** агент дополнительно получает скрытую часть с идентификаторами, путём и командой `bb openspec review resolve <id>`
