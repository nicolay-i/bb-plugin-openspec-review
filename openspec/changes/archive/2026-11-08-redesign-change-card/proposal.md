# Change: Карточка изменения по макету

## Why

Текущая карточка изменения — набор свёрнутых блоков и выпадающий список документов. По ней трудно за секунду понять состояние change: какие артефакты готовы, где ждут черновики замечаний, что меняется в спеках, какие разделы задач закрыты и какие треды работают с изменением. Есть утверждённый макет «Панель треда · карточка изменения» (400 px).

## What Changes

- Заменить свёрнутые блоки карточки изменения открытыми секциями макета: заголовок, артефакты, выполнение задач, треды, затронутые спеки.
- Список документов вместо выпадающего списка: строка на файл артефакта со статусом по схеме, счётчиками черновиков и открытых обсуждений; для дельт спек — счётчики ADDED/MODIFIED/REMOVED/RENAMED. Строка открывает документ, возврат — к карточке.
- Прогресс задач: общий «N из M», полоса и разделы `##` трекинг-файла с локальными счётчиками.
- Треды: связанные треды с отметкой текущего, отвязкой, «+ Связать тред» и счётчиком прочих связей треда.
- «Затрагивает спеки» — capability из дельт OpenSpec.
- Карточки спеки и архива используют тот же список документов и блок тредов.
- Заголовок показывает человекочитаемый title из OpenSpec, путь change и схему; панель — метку «только чтение».

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `openspec-visual-workspace`: добавляется требование к составу карточки изменения.

## Impact

- Host `detail` дополнительно вызывает `openspec show <change> --json --deltas-only` (только при наличии proposal.md, иначе CLI возвращает ошибку) и читает трекинг-файл задач для разделов.
- Новый server RPC со счётчиками замечаний по путям документов; схема БД не меняется.
- Требование добавляется к capability, которая пока существует только в `add-bb-openspec-visual-plugin`: архивировать этот change после него.
- Без новых зависимостей и без записи в файлы OpenSpec.
