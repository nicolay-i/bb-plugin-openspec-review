## Контекст

UI плагина — React в iframe BB, сервер — BB plugin SDK. SDK не сообщает локаль BB серверу; браузерная локаль доступна только в UI (`navigator.language`). `bb.sdk.threads.send` принимает части с `visibility: "agent-only"`; история промптов треда хранит только видимые части. Doc Review (`buildHandoffInput`) уже использует схему «видимый пузырь + скрытая агентская часть».

## Цели / Не цели

**Цели:** читаемый пузырь с номерами как на подсветке; правильная сверка очереди; 10 языков с автоопределением; явный переключатель колонки.

**Не цели:** RTL, перевод агентской части, хранение текста пузыря в БД.

## Решения

1. **Две части сообщения.** Видимая — Markdown: `**Комментарии к <файл> · N**`, далее для каждого `**Комментарий №<seq>**`, текст, цитата `> …` (до 180 символов, экранирование Markdown). Агентская — английская, с `[id] Comment #seq · Quote: …`, путём и инструкцией `bb openspec review resolve`. Комментарии сортируются по `seq`. Лимит 100 000 символов на сумму частей.
   - Альтернатива: одна часть с id в конце — отклонено, id мешают читать и не нужны человеку.
2. **Сверка очереди по пузырю.** Для `queuedId`, которого уже нет в очереди, пересобрать пузырь из комментариев этого сообщения на каждом из 10 языков; совпадение с текстом в истории → «отправлен», иначе → «открыт». Комментарии в очереди не редактируются, поэтому пересборка детерминирована.
   - Альтернатива: сохранять текст пузыря в БД — требует миграции; отклонено ради минимального изменения.
3. **Язык.** Настройка `language`: `auto` (по умолчанию) или один из 10 кодов. `auto` разрешается в UI: первый подходящий из `navigator.languages` (точное совпадение, затем по основному подтегу; `zh*` → `zh-CN`, `pt*` → `pt-BR`), иначе `en`. UI передаёт разрешённый код в RPC `send`; сервер валидирует его по списку и не угадывает сам.
   - Альтернатива: локаль сервера/хоста — не отражает пользователя; отклонено.
4. **Колонка.** На ширине ≥ 720 px — `border-left` по `--border` и отступ; подпись переключателя `{Показать|Скрыть} комментарии · N`.

## Риски / Компромиссы

- Длинные переводы ломают вёрстку (de, hi) → проверка вёрстки de/ja/hi и автотест полноты ключей.
- Качество машинного перевода → независимая вычитка переводов сабтредом.
- Пузырь в истории, изменённый BB (обрезка/нормализация), не совпадёт → комментарий вернётся в «открыт» (безопасная сторона: повторная отправка, без потери). Проверено на реальной истории для 0.1.0-формата пузыря.

## План миграции

Сохранённые `en`/`ru` остаются валидными значениями. Обновление — переустановка/обновление плагина из тега `v0.1.1`; откат — тег `v0.1.0`.
